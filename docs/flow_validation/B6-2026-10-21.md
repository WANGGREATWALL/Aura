# B6：机制对照、诊断驻留与版本取舍

日期：2026-10-21（UTC）。固定基线为已推送 dev `e3437895a92c38dc75b676df1ec025c271600d33`（B5）。本报告对应未提交/未推送的 B6 工作树。原始输出、二进制/源码哈希、实验配置、验证记录见 [数据 JSON](B6-2026-10-21-data.json)。全部问题仍在 [整改清单](../flow_remediation_plan.md) 追踪。

## 1 结论与范围

| 项目 | 本版决定 | 依据与边界 |
| --- | --- | --- |
| R03：ring/MPSC → mutex FIFO | **保留 ring/MPSC** | mutex 侵入式 FIFO 能保证接受后无队列分配，但主机集成 p95 没有稳定优势，孤立吞吐更差；不增加可切换生产后端 |
| R09：记录池 | **保留 Node/Edge/External 三类 Slab** | 稳态 helper 零额外分配；普通分配增加调用次数且没有一致延迟优势。承认高水位页直到实例销毁，不声称支持空闲页回收 |
| R09：闭包池 | **缩减为 64 字节一档** | 常见小闭包保留复用；删除 256/1024/4096 档，大闭包按真实尺寸分配，过对齐路径不变；实测较大闭包无新增库池驻留 |
| R13：DOT | **独立图捕获 + 值历史** | ID/名称/结构/状态/错误足以保留动态图；历史不持有 NodeRef、闭包或资源租约 |
| R13：timeline | **保留可裁剪的有界窗口** | 默认每 lane 1024，可配 1–65536；运行时仍关闭。提供停止/导出/reset/重启，不改为覆盖中的 ring，不将其当长会话实时性能工具 |
| R26：GPU 设备依赖 | **本版不纳入** | 普通 Task 依赖继续完整完成；连续提交可在同一任务及受支持的 wrapper 原生链内表达。独立设备边需要另行定义 enqueue/完成、context/清理/失败语义 |
| R26：自动大小核分类 | **本版不纳入** | 保留 SystemDefault/ExplicitCpuSet；主机 capacity 均匀，不能验证手机分级策略；不按 CPU 编号或缺失信息猜类别 |

R03/R09/R13 的主机验证与决策完成；R26 的本版范围已明确，真实设备证据仍为 USER_VALIDATION。**R01/X13 的 tiled/CPU 延迟未收口**，不据机制取舍或分配减少宣布总体性能验收通过；进入后续主机定位与 B7 集成追踪。B7、FlashPE 和目标设备尚未完成。

## 2 比较方法与复现

主机：Linux x86_64 / AMD EPYC，GCC 14.2.0、CMake 3.31.6、Ninja 1.11.1.4；允许 CPU 0–4、cgroup CPU 配额 4。Release，BUILD_TESTING=OFF，使用生产 aura、trace/perf 输出关闭。未锁频/温控；测量期间没有并行构建或测试，但共享云主机仍有噪声。表中 p50/p95 是 **5 次独立运行各自分位数的中位数**，不是合并分布，也不是性能 SLA。

第一组在相同 B5 源码上仅改变队列/分配器，5 个变体×5 轮轮换/反向顺序。第二组将原版、只缩小 payload 的冻结候选及最终 B6 对比，另测闭包、诊断、合成 GPU 链和最终机制。共保存 85 个成功进程输出（第一组 30、第二组 55），没有删除负结果。时间统计不运行在 aura_testing。

## 3 R03：队列对照

第一组集成结果，单位 µs，单元格 p50 / p95：

| B5 变体 | 外部空循环 1080/16 | managed 空循环 | 图像行循环 tile16 | 图像行循环 tile64 | 3 路扇出/汇合 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原版 ring + 池 | 18.85 / 29.11 | 31.49 / 52.66 | 174.99 / 261.35 | 187.76 / 312.54 | 795.84 / 1028.88 |
| 仅 mutex FIFO | 18.19 / 34.42 | 30.75 / 71.07 | 148.45 / 251.83 | 169.58 / 256.99 | 730.09 / 1123.30 |
| 仅普通 payload | 18.19 / 30.49 | 31.12 / 73.73 | 166.58 / 258.64 | 189.25 / 350.71 | 682.65 / 972.06 |
| 仅普通记录分配 | 18.60 / 26.74 | 31.45 / 62.26 | 139.11 / 259.32 | 172.33 / 278.65 | 802.09 / 1031.51 |
| 记录 + payload 普通分配 | 18.61 / 38.50 | 30.11 / 47.61 | 186.94 / 259.76 | 188.94 / 288.11 | 699.98 / 1040.43 |

mutex FIFO 的若干 p50 更好，但 managed p95 约增 35%、扇出 p95 约增 9%；没有证据支持整体替换。独立 16384 项 burst 和 4 producer/4 consumer 输出亦保留，不把孤立吞吐当业务收益。FIFO 自身大小 56 字节、ring 队列 4224 字节（本机）；两者接受/发布不分配。FIFO 每次 push 和 pop 尝试各取一次 mutex；16384 push+成功 pop 的 burst 至少 32768 次获取。ring 路径自身无 mutex，**这不是 Core 完整路径的锁次数统计**，不重复原评审“每任务 8–10 锁”的估算。

新增同一套小票号 ring/溢出与 FIFO 多生产/消费、暂停发布、立即复用测试，检查每个工作恰好一次。FIFO 的 publisher hook 在获取其 mutex 前暂停，不能用它证明持锁暂停仍有进展；ring 既有的 reservation/overflow hole 专项保持。六个冻结变体各通过 52/52 XFlow/XFlowPublic 测试，其中共用测试覆盖闭包构造回滚、对齐、析构/复用与上述队列契约。没有宣称 mutex 变体跑过所有 ring 专用运行期暂停 seam。

## 5 R13：值历史与可释放窗口

- `GraphHistory` 保存值批次，无 NodeRef/闭包/mm lease；一次提交先准备稳定记录，接受后在提交 latch 放行前发布。相同历史内不重复复制前驱链，避免每个动态后继重新存整条链。记录完成状态时用独立短锁；导出复制容器/字符串和 I/O 在 Core/History 锁外。
- 动态历史可随相关捕获句柄保留，仍有元数据成本。静态任务依赖/簇的真实执行引用不改变。导出某个子任务只输出其可达图，不带整份共享历史中的无关祖先/兄弟。诊断 OOM 不拒绝工作，保持 dropped。
- 新增 C ABI v1 增量函数 `au_flow_graph_capture`、`au_flow_trace_reset` 与 C++11 `setGraphCapture/resetTrace`；不改变既有符号和结果/句柄布局。旧 setTracing 保留组合开关。
- **显式捕获边界**：根接受时固定选择，后代继承；启用须在根提交前。中途 enable 不补旧根，disable 不停止已捕获作用域。这一边界已加入公开注释、迁移文档和测试。
- 时间线默认 OFF，构建 ENABLE_FLOW_TRACE 默认 ON 以兼容；OFF 时启用/导出返回 NotSupported、关闭/reset 成功，DOT-only 仍工作。容量默认 1024，非 ring 覆盖；满后计 dropped，应用通过 stop/export/reset/restart 分窗口采集。
- 并发 record/export/reset 通过共享存储 pin 保证存活。reset 要求 disabled，摘下当前窗口后旧 pin 可以继续收尾；不保证 reset 返回时所有旧 pin 或 OS PSS 都归零。关闭热路径只读开关，开启才付 pin 成本。

五轮诊断测量中位数：

旧存储约 13.50 MiB，新约 1.69 MiB，约减 87.5%（不含 allocator 元数据）。新测量仅开 DOT、旧版必须连带 timeline；动态捕获 PSS 不能据此单独分离所有收益。refs 检查与释放子句柄后仍可导出名称/错误/根因的测试直接验证没有诊断执行树保活。历史是轻量保留，并非零内存。

## 6 R26：GPU host gap 与 CPU 能力

`flow_gpu_gap_benchmark` 是 **主机时钟模拟的 FIFO 设备时间线**：5 段×500 µs，事件结束为预定 deadline，不是真实 GPU profile。每运行 3 次预热、31 次样本、124 条 gap。比较一个 Task 内连续提交，与 5 个普通 Task 依赖边；完整完成和 release 次数均检查。

| 模式 | B5 gap p50/p95 µs | B6 gap p50/p95 µs | B6 host total p50/p95 µs |
| --- | ---: | ---: | ---: |
| 单 Task FIFO 模型 | 0 / 0 | 0 / 0 | 2706.71 / 2887.94 |
| 普通 Task DAG | 855.95 / 893.40 | 856.60 / 908.94 | 6800.90 / 7036.39 |

0 是模型在命令提前提交时连续排期的结果，不是声称硬件零开销；约 0.86 ms 展示当前查询/清理/调度路径可引入间隙，不包括 A 的设备工作时间。**没有测到真实 GPU 空泡大小，也没有消除这一空泡。** 同 context 原生事件链模型、跨 context/staging 桥接、清理/失败传播已有回归继续通过；具体 DMA import/驱动/事件与 host 时钟分域需设备验收。

不在本版补 `.gpu()` 或改变普通 precede。需要模块化 GPU DAG 的使用方可先合并连续 enqueue 到同一 Task，但仅在 wrapper 自身支持直接链的路径有效；staging/Image/跨 context 仍可能桥接。将来设备边应明确受支持资源/context、失败后清理与双阶段状态后单独设计，属于新增契约，不是本轮遗漏功能。

CPU sysfs 观察保存在 JSON：允许的 0–4 五个核 capacity 均为 1024，无 core_type/cpufreq 信息。本版无足够异构设备证据支持分类 API；继续使用已有 SystemDefault/ExplicitCpuSet。不能将均匀或缺失 capacity 推断为大核，更不能规定固定大核编号。Android 大小核/热控策略由用户后续环境验证。
