## 3 可复现命令

在 Aura 根目录、已有构建工具的环境执行；可用独立目录重建，不需真机：

```sh
cmake -S . -B /tmp/aura-b5-cpu -G Ninja -DCMAKE_BUILD_TYPE=Debug -DENABLE_OPENCL=OFF
cmake --build /tmp/aura-b5-cpu -j4
ctest --test-dir /tmp/aura-b5-cpu --output-on-failure
/tmp/aura-b5-cpu/aura_test

cmake -S . -B /tmp/aura-b5-cl -G Ninja -DCMAKE_BUILD_TYPE=Debug -DENABLE_OPENCL=ON -DENABLE_OPENCL_HARDWARE_TESTS=ON
cmake --build /tmp/aura-b5-cl -j4
ctest --test-dir /tmp/aura-b5-cl --output-on-failure
/tmp/aura-b5-cl/aura_test

cmake -S . -B /tmp/aura-b5-asan -G Ninja -DCMAKE_BUILD_TYPE=Debug -DENABLE_OPENCL=ON -DENABLE_ASAN=ON
cmake --build /tmp/aura-b5-asan -j4
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 ctest --test-dir /tmp/aura-b5-asan --output-on-failure

cmake -S . -B /tmp/aura-b5-tsan -G Ninja -DCMAKE_BUILD_TYPE=Debug -DENABLE_OPENCL=OFF -DENABLE_TSAN=ON
cmake --build /tmp/aura-b5-tsan -j4
ctest --test-dir /tmp/aura-b5-tsan --output-on-failure

cmake -S . -B /tmp/aura-b5-prod -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build /tmp/aura-b5-prod -j4
c++ -std=c++11 -DAURA_STATIC -I inc test/flow_migration.cpp /tmp/aura-b5-prod/libaura.a -pthread -ldl -o /tmp/aura-b5-migration
/tmp/aura-b5-migration
cmake -DAURA_NM=/usr/bin/nm -DAURA_LIBRARY=/tmp/aura-b5-prod/libaura.a -P test/flow_production_symbols.cmake
```

最后一组手工链接为本次 Linux 主机命令，Android 应使用项目 CMake/Threads::Threads 和 log，不照搬 `-pthread/-ldl`。C11/C++11/C++17 的严格命令、旧消费者编译/链接方法及输入校验值在数据文件中记录。当前环境实际目录沿用 B0/B2 的构建目录名，但二进制已由 B5 源码重建，见日志/校验值。

## 4 格式与功能差异

[格式补丁](B5-2026-10-21-format.patch) 仅保存对 B4 的第一阶段机械 clang-format 差异（零 context）。可在 B4 源码用 `git apply --unidiff-zero` 重建中间状态，再比较最终代码中的契约注释、parallelFor、局部类型限定与消费者检查；不是直接对最终源码重放的补丁。功能改动与测试通过最终 diff 审查，未修改 .clang-format 或全仓格式化。

`au::flow::detail::invoke` 的两处调用保留全限定：带 std 参数的 C++17 消费者会经 ADL 看到 std::invoke。编译检查发现并纠正过度精简；最终 C++11/C++17 均通过。普通 async 的返回类型约束保持原样。
