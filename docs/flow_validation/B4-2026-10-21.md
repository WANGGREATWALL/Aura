| R19 | 新增状态/锁表、函数前置条件及 mm/OpenCL 边界审查；外部 token 溢出回滚的销毁移到 graph 锁外。驱动内部锁不在审查范围内 |

child 邻接在接受的同一 graph 临界区接入，在 finish 的临界区先摘除再移走 parent ref。child 的 accepted 引用和 parent reservation 保证借用链接寿命，不增加新的强引用环。搜索的 target/queued/next 字段都由 graph mutex 保护，提前发现环时也会在解锁前恢复。Draft 编辑现在同样通过该 mutex 使用 scratch；调用者仍须串行化同一 Draft 的命名、编辑、提交和销毁。

状态字段按 graph、worker、external、存储和 diagnostics 分组。Core 保留跨职责协调和私有共享状态，未为了文件行数引入额外分配或动态接口；executor 仍是较大的实现单元。后续改动应继续遵守锁表，不能把拆文件理解为可以分离各自的关闭生命周期。

## 测量方法

五轮交错执行，没有同时运行本批构建或测试。GCC 14.2、Release `-O3 -DNDEBUG`，主机 AMD EPYC 9V74，CPU 0–4、cgroup 配额 4 CPU，频率未锁定。共享主机与小样本有波动，所有原始输出均保留。

生产 CPU/idle 程序链接正常 aura。CPU 源码仍为 SHA256 `54de32f3350f7eba159dbb8feb7c3989668ad1aeb418470e905e04ab5e55ce3f`，B3 二进制与其报告中的哈希一致。各项 16 次预热、101 次计时，另用 25 次调用统计全局 C++ new，不覆盖 malloc/驱动分配。

另加 **instrumented graph benchmark**，仅链接 aura_testing。它固定预算 1，构造宽度为 32/128/512 的未完成组、256 个无关挂起根、0/7 层嵌套调用，预热 5 次后做 31 次零超时 wait。B3 仅插入相同的测试计时/计数，不改调度算法。图 benchmark 的时钟/计数会增加开销，不能当生产延迟或业务帧结果。

`wait_lock_ns` 的起点在取得 graph mutex 后，终点在 guard 释放前，覆盖搜索、目标标记恢复、祖先检查、wait 边设置及局部析构；不含取得锁的竞争、unlock 和计时器自己的最后计数更新。`search_ns` 只是其中的搜索段，不能代替完整检查区间。

### 等待图锁内检查

下表单位 µs：wait p50 为五轮各自 31 样本 p50 的中位数；锁内区间为五轮各自累计区间时间/31 的中位数，不是 p50。

| 组宽度 / 嵌套深度 | B3 wait p50 | B4 wait p50 | B3 锁内区间均值 | B4 锁内区间均值 |
| --- | ---: | ---: | ---: | ---: |
| 32 / 0 | 40.220 | 0.420 | 46.301 | 0.283 |
| 32 / 7 | 186.551 | 0.431 | 234.713 | 0.366 |
| 128 / 0 | 286.663 | 1.112 | 309.657 | 1.235 |
| 128 / 7 | 1529.108 | 1.132 | 1571.134 | 0.994 |
| 512 / 0 | 3249.524 | 4.667 | 3174.895 | 4.769 |
| 512 / 7 | 13564.953 | 4.647 | 14511.710 | 4.747 |

深度 0 时，B3 每次 wait 重复搜索 2 次；深度 7 时为 9 次。B4 均为 1 次。512 宽/7 深这一组的 31 次检查，B3 累计扫描全局活动节点 111,426,462 次，B4 为 0。B4 改为遍历可达节点/边，并一次标记多个目标；没有通过跳过间接等待环检查取得数据。

Node 的 sizeof 从 **584 增至 624 字节**，每节点增加 40 字节（约 6.85%），用于 3 个 child/sibling 指针和遍历 scratch。在当前 128 节点 slab 页上相当于约 5 KiB 的节点存储增量；池高水位/页释放策略仍归 R09/B6。这是明确的内存换时间取舍，不能说优化零成本。

### 模拟事件与退休回测

两端各 5/5 正常完成、退出码均为 0。模型在途的 200 ms 窗口查询中位数都为 97，预算降为 1 后都为 98；两端空闲 2.3 秒后的 worker 都为 0、进程线程数都为 1。B4 保留了 B3 的推进和退休行为。

B3：模型 ready→Task 终态中位数 1273.161 µs；退休后首任务 199.300 µs；空闲快照进程 PSS 1704 KiB。

B4：模型 ready→Task 终态中位数 878.496 µs；退休后首任务 187.192 µs；空闲快照进程 PSS 1648 KiB。

context switch 不是 OS 唤醒/耗电，模型事件不是真实 OpenCL。进程 PSS 还受代码映射、libc 栈缓存与驻留页影响，不能把两端 PSS 差异解释成 Node 存储减少；实际上 Node 更大，已单列记录。
