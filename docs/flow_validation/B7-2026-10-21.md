## 2 依赖、接口与安全边界

- flow 的直接/传递编译依赖无 gpu 实现头或 OpenCL 原生类型，生产 flow 对象无 au::gpu 未解析引用；最小 consumer 无 au::gpu 符号。允许的 log/mm/sys 等 Aura 依赖真实保留。
- 保留不透明 ExternalToken 和 query/finalize/release。提供方保持 event、fence、staging、租约与驱动操作的所有权；未指定来源的通用 query 错误默认 Flow，GPU 提供方显式填 OpenCL。
- GPU backend 使用明确的 initializeExecutor 保证静态析构顺序，不再借 tracingEnabled 初始化。teardown 模型在 queue profiling 开启时仍验证原生资源/事件全部释放，且自动 profiling 查询为零。
- 删除 6 个 C 符号：name、tracing、graph_capture、trace_reset、dot、trace（均有 au_flow_ 前缀），没有新增 C 符号。删除相应 C++ 诊断方法及 setName。**flow C ABI 升为 2**；需匹配头库重编，不承诺全部旧二进制兼容。结果/worker 布局、错误值及其余 C 函数保留。
- 生产不编译 testing.cpp，无 fault 宏或 trace 宏；C11/C++11/C++17 matching consumer 编译并运行通过。当前实现/锁文档删除失效的诊断描述，B0–B6 保留为明确标注的历史证据。

## 3 保留的 B7 修复与优化

X15：旧 B6 的 worker 已减少 ready、尚未登记 busy，新提交可能低估需求不扩容，随后 worker 进入阻塞主体使另一任务停滞。旧 B6 仅加 BeforeBusy seam/回归即可确定性 Timeout，原失败和小补丁留证。修复采用 SC ready/busy 增加与需求读取，分派登记 busy 后再次 grow；容量足够时只做原子快速判断，减少计数仍 relaxed，不替代队列或 worker 寿命协议。

同批保留 helper 先发布全部真实项、一次 post(accepted)/grow；最多三次 gate 发布锁合为一次，控制仍独立。删除无人读取的 gTileDepth，以 TileContext 统一约束和错误归属。旧合作睡眠测试等待 parent 主体已进入，交接窗口由新测试单独覆盖。没有借缩行移除 Job 关闭线性化、helper 完整 join 或间接等待环检测。

## 7 剩余验收与退出条件

- 用户已决定 NDK/ADB/设备后续自行验证。本地主机工作不重复索要设备；NDK r25c/API28/arm64 实际链接仍需确认，无 pthread 桩。
- 固定 FlashPE/GitLab refs、适配补丁、输入/算法/内存路径、NDK/驱动及生产参数；三引擎各自微基准，原始业务与最终候选端到端对照。当前未提供外部源码，不确认“5 宏/3 addPipeline”数量。
- QCOM/MTK 适用设备验证导入/cache/staging、资源寿命与失败清理、长时压力、退休/查询交接、线程/PSS/首次耗时、GPU 在途和空闲真实唤醒。可用时设备 TSan，不能据 x86 sanitizer 推导 ARM64 正确。
- GPU 普通完整边仍有 A 设备完成到 B 入队的主机间隙；设备时钟和主机时钟分域，单任务连续提交与普通 DAG 分开测，不把 A 自身执行算作开销。
- SDK 所有外部调用返回、句柄/资源销毁后再 dlclose；模型通过不替代真实 SDK/驱动卸载验证。R01/X13 和适用外部验收完成之前，B7/整轮不标 CLOSED。
