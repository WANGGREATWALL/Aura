## 实现与契约

- 外部同步 tiled 由栈上 JobScope 登记；不建 inline root，不进入通用 submit。接受与 Stopping 在同一 mutex 内裁定；计数覆盖 caller、helper、错误汇总和收尾，RAII 退出后通知关闭者。shutdown 同时等待 accepted Tasks 和 Jobs 为零。
- **waitAll 语义变更**：只快照已接受异步根及结构化后代，排除外部同步 Job。managed Task 的同步计算仍被父任务完成覆盖。tile 中的 waitAll/shutdown 返回 WouldDeadlock。排空不代替 dlclose 前确认外部 SDK 调用已返回。
- **tile 契约变更**：禁止发布异步 Task 或准备异步 GPU 工作；返回 StateInvalid，并记录到当前循环，忽略结果/void 回调仍失败。创建 Draft、编辑图、嵌套同步 tiled 和合法的已接受任务 wait 保留。需要异步 fan-out/GPU 的旧回调应把发布移到外层普通 Task。
- 每次回调通过 TileExtent RAII 安装错误接收器、停止标志和 mm sink；caller/helper/单参与者/嵌套/深栈串行均一致。协作 run 与 cleanup 保存、清空、恢复完整上下文。错误按最小已执行失败 offset 选择；保留同码的 native/domain/cause，区分捕获异常与业务返回相同整数。
- 最多 3 个可选 helper 使用固定数组、Node 池和专用接受路径；不建立一般图批次/索引/入度容器。保留 Node 身份和 parent reservation，以维持等待环与结构化完成。每次调度最多连续 8 个 tile 再回队；caller 持续领取。存储/线程准备失败时 caller 接管。
- **新增 X12**：内部 helper 不能用可能因图检查分配失败而提前返回的通用 wait 后忽略结果，否则仍运行的 helper 会借用已失效 Loop。现在使用不可提前失败的 joinHelper；managed parent→helper 的完成依赖在接受时已经存在，回调发起的等待仍经普通环检测。helper 全部结束后才能释放 Loop。

环境：Linux x86_64 / GCC 14.2 / CMake 3.31.6 / Ninja 1.11.1.4；允许 CPU 0–4，cgroup 配额相当于 4 CPU。Release CPU-only 生产库，trace/perf 输出关闭。每例 16 次预热、101 次计时、另取 25 次统计整个进程的 C++ new 次数/请求字节；不包含 malloc/驱动内部分配，不表示零成本或零冷分配。

已确认预热外部循环的 C++ 分配从 6～约 36 次降为 0；managed 测量包含一次普通 enqueue/wait，保留 6 次分配。单 tile 延迟下降；1080p tile16 样本改善。**1080p 空循环 p50 约翻倍，tile64 与扇出/汇合部分分位数也变差**；其他轮次存在不同方向，不能据此宣布全面加速或稳定回归比例。特别是空循环退化仍是 X13，须继续定位 helper 接受/唤醒/join 的成本，最终按同一套微基准回测。没有 FlashPE 帧结果，也没有设备功耗改善证据。

另做了五轮三候选对照：逐 tile helper（K=1）、批量 K=8、逐个接受/发布 helper（K=8）。managed 空循环 p50 分别约 34.5/31.3/33.5 µs，p95 约 1124/134/186 µs；图像循环与无关扇出存在波动，不能证明 K=8 对所有负载最优。保留 K=8 的有界实现；未采用逐个发布方案，因为未稳定改善空循环。完整实验及准确补丁在原始 JSON 中，生产代码未混入试验开关。
